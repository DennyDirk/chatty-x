# Проверка отправки Telegram

Импорт истории работает независимо от обработчиков отправки. Стенд на
`http://localhost:8089` из `compose.telegram-test.yaml` по умолчанию запускается
с `WORKERS_ENABLED=false`: он позволяет проверять подключение и историю.
В этом режиме ручная отправка и автоответы не выполняются. Интерфейс показывает
причину, а новый ручной запрос отклоняется с `PROCESSING_DISABLED` до записи
в очередь. Текст остаётся в поле ответа. Старый повтор с уже принятым ключом
возвращает сохранённый результат, не создавая второе сообщение.

## Обновить и проверить накопленную очередь

Все команды выполняются из `C:\Users\des\IdeaProjects\chatty-x`.
Сначала оставьте `WORKERS_ENABLED=false` в `.env.telegram-test` и обновите код:

```powershell
docker compose --env-file .env.telegram-test -f compose.telegram-test.yaml up -d --build backend web
```

Откройте переписки. Сообщения со статусом «В очереди на отправку» ещё не доставлены.
В прежней версии они могли накопиться даже с отключёнными обработчиками. Для
каждого ненужного сообщения нажмите «Отменить». Оставленные READY будут обработаны
после включения, поэтому проверяйте их до следующего шага. Глобальная остановка
автоответов не отменяет сообщения владельца. UNKNOWN/«Отправка не подтверждена»
не повторяется автоматически; для него есть отдельная сверка доставки.

## Включить ручную отправку

В `.env.telegram-test` установите ровно одно значение:

```dotenv
WORKERS_ENABLED=true
```

Примените его пересозданием backend; обычный `restart` не читает новые переменные:

```powershell
docker compose --env-file .env.telegram-test -f compose.telegram-test.yaml config --quiet
docker compose --env-file .env.telegram-test -f compose.telegram-test.yaml up -d backend
```

Если WORKERS_ENABLED уже задан в окружении PowerShell, он имеет приоритет над
файлом; уберите его для использования файла: `Remove-Item Env:WORKERS_ENABLED`
(только если он существует). Не выводите полный Compose config: в нём есть секреты.
Проверить итоговый режим можно в авторизованном `GET /api/v1/runtime`; ответ
содержит только флаги, без ключей. В переписке исчезнет предупреждение о выключенной
отправке. При необходимости завершите Telegram-вход через кнопку подключения.

Оставьте автоматизацию аккаунта и общую автоматизацию выключенными. В выбранном
согласованном тестовом чате напишите один ручной ответ. Ожидаемый путь:
«В очереди на отправку» → «Отправляем» → «Ожидаем подтверждения» → «Отправлено».
Быстрые промежуточные состояния могут не успеть появиться на экране. Финальное
сообщение должно быть видно в Telegram ровно один раз, а чат остаётся на паузе.
Ручной ответ не требует ключа модели, бюджета AI или разрешения автоответов.

WORKERS_ENABLED включает также обработку памяти и сверку истории; если ключ
модели уже настроен, фоновые задания памяти могут использовать платный API.
Рабочую конфигурацию VPS этот тест не заменяет.

## Проверить автоответы отдельно

В «Характере» укажите ключ OpenAI локально через интерфейс и сохраните нужный
бюджет. На вкладке «Автоматизация» включите «Разрешить автоответы в выбранных
чатах» и сохраните настройки. В «Аккаунтах» включите «Разрешить автоматизацию
аккаунта». В нужном выбранном чате дождитесь завершения импорта и нажмите
«Возобновить». Интерфейс показывает оставшиеся причины, если один из этих шагов
не выполнен. Подключение аккаунта само по себе ни одно разрешение не включает.

После возобновления пришлите новое входящее с тестового собеседника. Старые
импортированные вопросы и сообщения, прочитанные до возобновления, не запускают
ответ задним числом. Серия сообщений объединяется после восьми секунд тишины;
генерация и дополнительная задержка 2–6 секунд требуют ещё времени. Тихие часы,
лимит расходов, ошибка модели или правило передачи владельцу могут остановить
автоответ; конкретная причина показывается в чате. В production нет подмены
ответа тестовой моделью при отсутствующем ключе.

Ручной ответ снова ставит чат на паузу до явного «Возобновить». Для завершения
теста выключите разрешения автоматизации. Чтобы остановить и ручную очередь,
верните `WORKERS_ENABLED=false` и выполните `up -d backend`; уже переданный
Telegram запрос нельзя гарантированно отозвать. Тома и секреты не удаляйте.

Запишите результат ручной проверки без текста переписок, номеров и ключей.
Автоматические проверки с fake-адаптером подтверждают правила очереди, но не
доказывают реальную доставку Telegram или качество ответов модели.
