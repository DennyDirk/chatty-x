# Проверка авторизации Telegram

Этот стенд проверяет вход личного **тестового** аккаунта через production-адаптер
TDLib. Он отделён от demo и базы IntelliJ. Автогенерация, отправка очереди и
обновление памяти отключены через `WORKERS_ENABLED=false`. Периодическая очистка
данных остаётся включённой. Это стенд авторизации, а не конфигурация рабочего сервиса.

## Что проверено автоматически

`TelegramAuthorizationTest` подменяет только транспорт TDLib. Проверяются QR и
его обновление, переход с QR на номер, код, пароль 2FA, email и код email,
устаревшая форма, ошибки инициализации, повторные события, изоляция аккаунтов,
закрытие клиента, поздние результаты старого входа и отключение во время getMe.
React-тесты проверяют очистку секрета при смене шага, показ фоновой ошибки,
обновление формы после конфликта и замену QR. Нативную загрузку отдельно проверяет
`compose.tdlib-test.yaml`. Эти проверки не подтверждают вход в настоящий Telegram.

## Подготовка

Нужны Docker Desktop в режиме Linux, доступ к сети, отдельный существующий
Telegram-аккаунт, Telegram на телефоне и собственные `api_id` / `api_hash`,
полученные в разделе API development tools на [my.telegram.org](https://my.telegram.org).
Используйте согласованные тестовые чаты; основание для обработки реальных
переписок остаётся отдельным пунктом M0. Ключи, QR, коды и пароль не отправляйте в
задачи, скриншоты или журналы.

В PowerShell из `C:\Users\des\IdeaProjects\chatty-x`:

```powershell
node infra/init-env.mjs --demo
if (!(Test-Path -LiteralPath .env.telegram-test)) {
    Copy-Item -LiteralPath .env -Destination .env.telegram-test
}
```

Локально откройте `.env.telegram-test`, установите действительные
`TELEGRAM_API_ID` (положительное число) и `TELEGRAM_API_HASH`. Остальные случайные
секреты уже созданы предыдущей командой. Файл исключён из Git; существующий файл
не перезаписывайте. Переменные режима demo из копии не используются этим стендом:
production и отключение обработчиков заданы явно в Compose. Не меняйте
`DB_PASSWORD` или `MASTER_KEY` после появления данных без процедуры миграции.

Сначала соберите и проверьте закреплённую TDLib, затем запустите отдельный стенд:

```text
docker compose -f compose.tdlib-test.yaml run --build --rm tdlib-check
docker compose --env-file .env.telegram-test -f compose.telegram-test.yaml config --quiet
docker compose --env-file .env.telegram-test -f compose.telegram-test.yaml up -d --build
docker compose --env-file .env.telegram-test -f compose.telegram-test.yaml ps
```

Откройте `http://localhost:8089`. Создайте владельца этой отдельной базы, используя
`BOOTSTRAP_TOKEN` из `.env.telegram-test`, пароль и приложение TOTP. Системные часы
компьютера и телефона должны быть синхронизированы. В «Аккаунтах» добавьте Telegram,
затем откройте «Подключение». Разрешение автоматизации оставьте выключенным.

## Ручной сценарий и ожидаемый результат

1. Выберите «Вход по QR». После ожидания появляется QR; отсканируйте его через
   Telegram → Настройки → Устройства → Подключить устройство. При обновлении QR
   в форме используется новая ссылка. Если Telegram требует 2FA, появляется
   отдельное пустое поле пароля. После успеха — «Аккаунт подключён».
2. Для независимой проверки номера отзовите **только сессию Chatty-X** кнопкой
   «Отозвать сессию», дождитесь её закрытия, снова откройте подключение. Выберите
   QR, затем «По номеру». Сначала видно завершение предыдущего входа, затем поле
   номера. Введите международный номер, актуальный код и пароль, если запрошен.
   Доставка кода определяется Telegram; SMS не гарантируется.
3. На шаге кода один раз введите неверный тестовый код: форма должна показать отказ
   и позволить повторный ввод. Не перебирайте коды и не повторяйте запросы при
   ограничении частоты. Если Telegram запросит email, проверьте соответствующий
   шаг; не объявляйте эту ветку проверенной, если она не появилась.
4. Отключите сессию и дождитесь завершения. Повторное подключение не должно
   выдавать ошибку блокировки каталога TDLib. Проверьте в Telegram список устройств:
   отозванной сессии Chatty-X там больше нет. При ошибке отзыва нельзя считать,
   что доступ уже отозван; завершите именно эту сессию через Telegram.
5. Убедитесь, что подключение не включило автоматизацию. Не выбирайте и не
   импортируйте реальные переписки на этом шаге. Проверка истории и доставки
   остаётся следующей отдельной задачей.

Регистрация нового аккаунта и неподдерживаемые дополнительные требования Telegram
отображаются как «Нужно дополнительное действие». Не пытайтесь обходить их.

Сохраните в `docs/validation.md` дату, ревизию кода, способ входа, появившиеся
этапы, результат и категории ошибок. Номер, ключи, коды, QR-ссылки и содержимое
переписок в отчёт не включаются.

## Остановка и повторный запуск

```text
docker compose --env-file .env.telegram-test -f compose.telegram-test.yaml down
```

Команда сохраняет отдельные тома `chatty-x-telegram-test_postgres` и
`chatty-x-telegram-test_application`. Не добавляйте `-v`: для обычной остановки
удалять данные не требуется. Повторный `up -d` использует прежние данные.
Остановка контейнера сама по себе **не отзывает** Telegram-сессию; для отзыва
используйте кнопку приложения либо список устройств Telegram.

## Основание переходов

Состояния обновляются событиями TDLib. При смене способа входа приложение ждёт
`authorizationStateClosed`, прежде чем повторно открывать каталог того же аккаунта.
Устаревшие события прежнего клиента игнорируются. В UI данные шага очищаются,
а запрос с уже неактуальным типом шага отклоняется с HTTP 409.

Контракты: [авторизация TDLib](https://core.telegram.org/tdlib/getting-started),
[QR-запрос](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1request_qr_code_authentication.html),
[запрос номера](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1set_authentication_phone_number.html).
