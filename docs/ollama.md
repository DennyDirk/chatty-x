# Локальные ответы и память через Ollama

Chatty-X поддерживает локальную `qwen3:8b` для текстовых ответов и извлечения памяти.
API-ключ и баланс OpenAI для этого режима не нужны. Компьютер с Ollama должен
оставаться включённым. Запросы не оплачиваются провайдеру; электроэнергия и ресурсы
компьютера не учитываются в расходах Chatty-X.

Это первый локальный вариант: одна модель, контекст 4096 токенов, максимум
768 токенов результата, один запрос Chatty-X одновременно для ответов, памяти
и площадки. Остальные фоновые задания остаются в PostgreSQL и повторяются позже.
Фото и голосовые требуют ручного ответа; автоматического обращения к OpenAI нет.

## Применить обновление на существующем Telegram-стенде

Ollama уже должна работать на Windows и содержать модель. Проверка в PowerShell:

```powershell
ollama list
```

Если `qwen3:8b` отсутствует, выполните `ollama pull qwen3:8b`. Chatty-X сам ничего
не скачивает. Для текущего Docker Desktop адрес хостовой Ollama уже задан в Compose:
`http://host.docker.internal:11434/api/chat`. Проверка этого адреса новым адаптером
на этой машине прошла 2026-10-05. Менять настройки сети Ollama для этой машины
не потребовалось.

В Chatty-X остановите автоответы глобальной кнопкой. Перед обновлением проверьте
очередь ручных сообщений: глобальная остановка AI не останавливает ручные отправки.
Из `C:\Users\des\IdeaProjects\chatty-x` выполните:

```powershell
docker compose --env-file .env.telegram-test -f compose.telegram-test.yaml up -d --build backend web
```

Команда сохраняет существующие тома, владельца и Telegram-сессию. Миграция V7
добавляет настройку провайдера; значение по умолчанию остаётся OpenAI. `WORKERS_ENABLED`
в `.env.telegram-test` должен быть `true` для обработки отправок. Если он выключен,
порядок проверки очереди и включения описан в [telegram-sending.md](telegram-sending.md).
Не используйте `down -v` или удаление базы для обновления.

Откройте [Chatty-X](http://localhost:8089), обновите страницу:

1. «Характер» → «Автоматизация» → «Провайдер ответов и памяти» → «Ollama — на моём компьютере».
2. Сохраните настройки. Это не включает автоматизацию, но отменяет устаревшие
   заготовки предыдущего провайдера. Уже переданный Telegram запрос остановить нельзя.
3. В «Площадке» отправьте синтетическую английскую реплику:
   `Hey, finally finished that project. Completely exhausted lol`.
   Должен появиться английский текстовый ответ. Площадка ничего не отправляет в Telegram.
4. Только после проверки включите общие автоответы, разрешение аккаунта и нажмите
   «Возобновить» в выбранном, импортированном тестовом чате. Отправьте новое входящее
   с согласованного второго аккаунта. Сообщения старше часа могут требовать ручного ответа.

Сохранённый OpenAI-ключ удалять необязательно: в локальном режиме он не используется.
Нулевой месячный бюджет облачного API не блокирует локальные ответы. Журнал расходов
показывает `ollama/qwen3:8b`, число токенов и нулевую стоимость успешных запросов.
Для возврата выберите OpenAI и сохраните; облачный режим снова требует ключа и бюджета.

## Размещение и ошибки

При прямом запуске production JVM на хосте адрес по умолчанию
`http://localhost:11434/api/chat`. Профиль IDE `local` по-прежнему демонстрационный:
он возвращает фиксированный ответ, даже если выбрать Ollama. Реальная локальная
модель используется в production-режиме, включая Telegram-стенд на 8089.

Для другого размещения сервер читает `OLLAMA_CHAT_URL` как полный адрес `/api/chat`.
Этот адрес задаётся окружением backend, а не сообщениями или настройками браузера.
На VPS Ollama должна быть доступна самому VPS; `localhost` там не означает ваш ноутбук.
Не публикуйте незащищённый Ollama API в интернет. Compose здесь рассчитан на уже
проверенный Docker Desktop; другую сеть следует проверить отдельно.

| Сообщение/код | Действие |
|---|---|
| `LOCAL_MODEL_UNAVAILABLE` | Запустить Ollama, проверить адрес со стороны backend |
| `LOCAL_MODEL_NOT_FOUND` | Скачать именно `qwen3:8b` на машине Ollama |
| `LOCAL_MODEL_TIMEOUT` | Уменьшить нагрузку; таймаут запроса не больше 90 секунд |
| `MODEL_BUSY` в площадке | Повторить через несколько секунд; фоновые задания повторяются сами |
| `LOCAL_MEDIA_UNSUPPORTED` | Ответить на вложение вручную |
| `CONTEXT_LIMIT_REQUIRES_OWNER` | Ответить вручную или сократить профиль/примеры |
| `INVALID_MODEL_REPLY` / `MODEL_INCOMPLETE_RESPONSE` | Проверить запрос в площадке; неисправный результат не отправляется |

Сначала сохраняются правила профиля и вся текущая серия, затем доступное место
занимают старые сообщения, факты и резюме. При переполнении удаляется только
дополнительный контекст запроса, а не сохранённая история. Ограничитель использует
консервативный размер UTF-8 с резервом под шаблон и ответ. Слишком большая
обязательная часть требует владельца, вместо скрытого обрезания новых реплик.
Это ограничивает доступный контекст маленькой модели; оценка качества M9 ещё нужна.

## Проверки для разработчика

Обычные проверки не требуют Ollama и не обращаются к внешним аккаунтам:

```text
docker compose --profile test run --rm backend-check
docker compose --profile test run --rm frontend-check
docker compose --profile test rm -sf db-e2e backend-e2e web-e2e
docker compose --profile test run --build --rm e2e
```

Опциональная проверка установленной локальной модели новым Java-адаптером
использует только синтетические английские сообщения и факт о переезде:

```text
docker compose --profile test run --rm backend-check mvn -B -Dtest=OllamaLiveCheck -Dollama.smoke.url=http://host.docker.internal:11434/api/chat test
```

Имя `OllamaLiveCheck` намеренно не входит в обычный Maven test/verify.
Ожидается `BUILD SUCCESS`, английский ответ и факт с `subject=contact` и ID
синтетического источника. Это точечный smoke, а не полная оценка естественности.
Промпты версии `reply-v2`, `memory-v2`; исходный `reply-v1.txt` сохранён.

Контракты сверены с официальными [Chat API](https://docs.ollama.com/api/chat),
[structured outputs](https://docs.ollama.com/capabilities/structured-outputs)
и [thinking](https://docs.ollama.com/capabilities/thinking): запрос содержит schema,
`stream=false`, `think=false`; внутренние рассуждения не запрашиваются и не сохраняются.
