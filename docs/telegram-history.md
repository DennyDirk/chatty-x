# Проверка импорта истории

Владелец подтвердил успешный вход Telegram 2026-09-25. Следующая проверка касается
истории одного выбранного тестового личного чата. Автоответы на стенде отключены.

## Обновить стенд

В PowerShell из `C:\Users\des\IdeaProjects\chatty-x`:

```text
docker compose --env-file .env.telegram-test -f compose.telegram-test.yaml up -d --build backend web
```

Откройте `http://localhost:8089` и обновите страницу. Имеющиеся данные и каталог
Telegram-сессии сохраняются в томах. Миграция V6 добавляет признаки запуска
импорта. Удалять тома, сбрасывать владельца или копировать ключи заново не нужно.
Если Telegram потребует повторный вход, пройдите его через «Подключение».

## Проверить один чат

1. Выберите личный чат с согласованными тестовыми сообщениями. При необходимости
   откройте «Аккаунты → Обновить чаты», затем «Диалоги» и нужную переписку.
2. Нажмите «Выбрать чат». Появится число загруженных сообщений. Загружаются
   максимум 1000 сообщений за последние 30 дней. Достижение лимита считается
   успешным завершением ограниченного импорта, а не загрузкой всей жизни чата.
3. После завершения проверьте несколько текстов/дат по Telegram. История может
   занимать несколько страниц по 50 сообщений; кнопка «Ранее» открывает старые.
   Фото и голосовые истории пока могут отображаться как HISTORICAL: загрузка
   содержимого исторических вложений не входит в этот шаг.
4. Нажмите «Загрузить заново». Старые строки остаются, дубли не появляются,
   автоматизация остаётся на паузе. Никаких исходящих из-за старых вопросов
   быть не должно.
5. Если загрузка достаточно долгая, нажмите «Отменить загрузку». Уже сохранённые
   страницы остаются доступны. «Повторить загрузку» начинает обход заново без
   дублей. Если загрузка завершилась раньше клика, отменять уже нечего.
6. При желании попросите тестового собеседника отправить новую реплику во время
   загрузки. Она должна появиться один раз; Chatty-X не должен автоматически
   ответить. Ручной ответ в Telegram сохраняет паузу.

«Возобновить» пока не нажимайте. `WORKERS_ENABLED=false` на этом стенде отключает
отправку очереди, генерацию, память и периодическую сверку. Первичный импорт
по явному действию владельца работает независимо от этой настройки. Проверка
истории не доказывает работу автоматической сверки после длительного отключения.

## Ошибки и повтор

Если страница недоступна, сохраняется уже загруженная часть и показывается
«Не удалось загрузить всю историю». Проверьте подключение аккаунта и нажмите
«Повторить загрузку». Если приложение перезапустилось во время загрузки,
появится отдельное сообщение о прерывании. Автоответы сами не возобновляются.

Отмена действует на локальную обработку. Запрос истории, уже переданный Telegram,
может завершиться, но его результат после отмены не записывается. После ошибки
или отмены начальное извлечение памяти не планируется.

В отчёте достаточно указать результат, число загруженных сообщений, наличие
дублей и категорию ошибки. Тексты, имена собеседников, номера и ключи не нужны.

## Автоматические проверки

`HistoryImportIT` проверяет границы времени/числа сообщений, повторный импорт,
обе очередности страницы и живого сообщения, отмену с немедленным повтором,
снятие выбора, частичный сбой, отсутствие продвижения курсора, восстановление
после перезапуска, отмену готового автоответа и изоляцию чатов. Используются
синтетические сообщения, фиксированные часы, отдельный PostgreSQL и блокировки
тестового ответа вместо ожидания реальных задержек Telegram.

Протокол допускает страницы меньше запрошенного лимита; короткая страница сама
по себе не завершает импорт. Контракт:
[TDLib getChatHistory](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1get_chat_history.html).
